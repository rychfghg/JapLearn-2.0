# Expression Match context refactor

- Retains the two-target matching game, all three image sets, exact-phrase audio and balanced answer positions.
- Both full situation captions remain visible and screen-reader labelled. They establish intent and relationship when an illustration cannot show an abstract distinction (formal request, gratitude, past apology).
- Missing or identical normalized captions are excluded before a round. This is a structural guard, not an automated judgment of Japanese pragmatics. Instructor review of complete image/caption pairs remains necessary, especially expressions that can fit many contexts.
- Every fourth question is a labelled caption-only context check (5 in a 20-question round). This reduces direct picture dependence, but reused captions and hints still make this supported practice, not proof of independent mastery or transfer to a new situation.
- Failed images offer retry and the full accessible caption for practice. Picture questions cannot record any scored answer (correct or incorrect) until both images load. The technical notice saves evidence without changing score, mistakes or question position. Intentional caption-only checks remain scored. An unresolved missing source must be corrected before that picture question can be scored; learners can save and return without penalty.
- All 60 hints explain the expression's purpose and contrast the two situations. Exact built-in scenario pairs use the revised bundled hint even if a server/cache still carries an older hint. The backend seeder also refreshes matching built-in records without overwriting valid teacher-authored contexts.
- Only active, level-matching set-1 published questions are selected. Known broken expressions (including dot-only situations or missing answer choices) are replaced with their complete authored version, retaining the published question ID. Invalid unknown rows and duplicates cannot enter the round; unused authored questions fill their gaps, providing 20 unique expressions per level. These authored versions use the existing exact-pair artwork and phrase audio. Valid published questions are retained. Backend seeding repairs complete known scenario pairs and fills missing authored expressions by identity, not raw row count; repeated server startup does not create new copies.
- Per-question records include question/phrase identity, both contexts, chosen context/position, correct position, picture versus caption-only mode, outcome, hint use, audio requests and timestamp. A blocked media-error selection is TECHNICAL_INTERRUPTION, not INCORRECT. Records are saved in local/server checkpoints and completed attempts. Backend totals derive from scored records only. Legacy attempts without records remain readable; no historical detail is invented.
- The progress API adds expressionBreakdown (expression and mode, correct/incorrect/technical counts, confused contexts). Results show picture versus caption-only performance. This is not a new teacher-dashboard page.
- Version-3 checkpoints require the exact cleaned question IDs and consistent sequential scored evidence. Older/mismatched checkpoints restart safely after content replacement rather than restoring totals from broken questions; completed past attempts are preserved.
- Japanese is shown above Romaji in the draggable phrase. Tap-to-answer supplements dragging.
- Each level opens with explicit Start/Continue instructions, including scoring and caption-only questions. Restart and Play Again reopen those instructions.
- Three-dot menu pauses audio/input, resumes, saves and returns, or asks for confirmation before restarting. Restart resets only the current run, never submits unfinished work as a completed attempt, and preserves past completed attempts.
- Account-scoped local and server checkpoints include question IDs and question evidence. Ordered snapshot writes prevent an older save from overtaking a newer one. Leaving during feedback saves the next unanswered question. Resume validates the exact cleaned sequence and restores correct/mistake counts from scored evidence rather than old totals. Final evidence can reopen results after an interruption before completion was saved.
- Header shows earned/possible points. Every game popup shows level, earned/possible points and correct/total matches; stars are in popups rather than the header. Popup content can scroll on short screens.

Validation: run `node scripts/check_expression_match_refactor.cjs` and backend `mvnw -Dtest=ExpressionMatchEvidenceTest test`. These cover assets, loader fixtures, evidence normalization/serialization and checkpoint logic, not real-device interactions. Backend changes add optional fields to attempts/runs and an expression breakdown in the progress response. Deploy the backend support before publishing the frontend; an older backend will not retain new fields. No deployment, live database mutation or OTA publication was performed.
