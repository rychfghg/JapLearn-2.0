# Politeness: relationship and setting

- Retains 30 existing scenarios (5/10/15 by level), NPC dialogue/audio, characters and story flow. No new learning distinctions or question topics were added based on unsupported assumptions about students.
- Every scenario names the communication partner's relationship and the learner's role before choices. Existing settings include teachers, unfamiliar adults/staff, a customer/client and senior colleagues. There are no existing close-friend-only questions; no new friend module was invented merely to fill a category.
- Each of 90 choices has a contextual explanation. Casual expressions are described as appropriate in other relationships where relevant, not universally bad. Unsupported personality judgments such as arrogant/rude are no longer used as automatic feedback.
- Several valid ordinary-polite alternatives are accepted alongside highly formal model answers. More formal does not automatically mean more appropriate. The highly formal meal compliment is explained as traditional, not taught as the only correct polite answer.
- Published questions matching the complete built-in prompt/NPC line receive the same guidance. Other published content must supply a relationship and learner role; unspecified relationships do not silently become scored scenarios. Optional backend fields support this metadata and per-choice feedback/acceptability.
- New attempt records store selected Japanese, accepted options, relationship, role, prompt, hint use and timestamp. Existing attempts only contain aggregate totals: the specific historical mistakes cannot be identified from this code/data, and no historical per-question answers are fabricated. Resumed legacy totals do not magically gain missing answer evidence. Review actual new response records (or a supplied response export) before selecting additional content.
- A synchronous answer lock prevents double-scoring. Replaying after an answer returns to that answer's feedback instead of allowing a second score. Bundled NPC audio/Romaji is matched by dialogue text instead of arbitrary published question order.

Validation: `node scripts/check_politeness_context.cjs`; targeted TypeScript/build and backend serialization checks. Device testing and Japanese-instructor review of contextual judgments remain necessary. This is not a new teacher-analysis dashboard. Backend deployment must precede frontend publication for new fields to persist. No deployment/OTA performed.
